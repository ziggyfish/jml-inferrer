\subsection{Synthesis: the gap this article addresses}
\label{subsec:rw-gap}

The ten preceding subsections traverse a wide arc---from the deductive synthesis and refinement calculi that first treated a program as derivable from its specification \cite{manna1980deductive,back1998refinement,morgan1994programming}, through the modern wave of large-language-model (LLM) code generation and its weak-oracle critique \cite{chen2021codex,liu2023evalplus,zhang2025hallucination}, the agentic and multi-agent frameworks that now drive repository-scale change \cite{yang2024sweagent,hong2024metagpt,liu2024llmagentse}, the design-by-contract and deductive-verification lineage that supplies a machine-checkable notion of correctness \cite{meyer1992dbc,leavens2006jml,cok2014openjml}, the spec-inference and loop-invariant literature \cite{ernst2007daikon,flanagan2001houdini,kamath2023loopy}, the counterexample-guided synthesis and verified-codegen efforts that close a proof loop around the model \cite{solarlezama2008sketching,sun2024clover,misu2024dafny}, the test-oracle and circularity hazards of self-graded generation \cite{barr2015oracle,liu2026oracle}, the behavioural-compatibility and breaking-change work that frames version evolution \cite{mostafa2017behavioral,jayasuriya2024understanding,foo2018efficient}, to the requirements-extraction, traceability, and natural-language-to-formal translation that govern where a recovered contract comes from \cite{antoniol2002recovering,merten2015issuetracking,endres2024nl2postcond}. Rather than restate those surveys, this closing subsection draws the threads together and states precisely the gap the present article fills.

Each line of work optimises one edge of the problem the emerging spec-driven lifecycles leave open, and each does so in isolation. The verification community has long possessed a machine-checkable contract layer with independent authority over an implementation \cite{meyer1992dbc,cok2014openjml,leino2010dafny}, but it presupposes that a human writes the formal contract by hand and says little about how an agentic lifecycle should obtain, ratify, or evolve that contract. The counterexample-guided synthesis tradition \cite{solarlezama2008sketching,alur2013sygus} and its LLM-era descendants \cite{sun2024clover,misu2024dafny,mugnier2025dafnypro} close a proof loop around a generator, but typically against a contract that is fixed in advance or, worse, drafted by the same model that writes the code---reintroducing the self-grading circularity that the weak-oracle and oracle-generation critiques warn against \cite{liu2023evalplus,liu2026oracle}. The natural-language-to-formal translators \cite{cosler2023nl2spec,endres2024nl2postcond,ma2025specgen} produce a candidate contract from informal intent and even validate it against sampled buggy code, but they neither confront the ratification problem---that the human chose natural language precisely because they will not read formal text---nor verify the synthesized code against that contract over \emph{all} inputs. The spec-mining and invariant-inference tools \cite{ernst2007daikon,ammons2002mining,si2018learning} recover likely properties from code or traces, but a property mined solely from an implementation describes what the code \emph{does}, not what it \emph{should} do, and so cannot by itself distinguish a faithful contract from an encoded bug. Finally, the breaking-change and behavioural-compatibility literature \cite{mostafa2017behavioral,ochoa2022breaking,jayasuriya2024understanding,islam2025byam} measures and sometimes repairs incompatibilities after the fact, but does not treat a contract change as a first-class lifecycle event whose blast radius can be computed without running a single client.

Crucially, no prior line of work combines these capabilities into a single reference development pipeline. The gap this article addresses is precisely that integration, along five dimensions that no existing system unites:

\begin{enumerate}
  \item \textbf{A machine-checkable formal-contract layer with independent authority.} The contract against which code is verified is a set of provenance- and assurance-tagged obligations expressed in the Java Modeling Language (JML) and discharged over all inputs by OpenJML extended static checking \cite{leavens2006jml,cok2014openjml}, and---unlike self-graded LLM pipelines \cite{liu2026oracle}---it is authored by an elaborator role that never sees the implementation, so the verifier never grades its own author.
  \item \textbf{Example/Socratic ratification that closes the ratification gap.} Rather than asking a human to confirm formal text they cannot read, the pipeline renders each contract as concrete checkable examples and surfaces only the boundary decisions it had to resolve, turning ratified examples into pinned oracles. The interactive NL-to-formal loops of \cite{cosler2023nl2spec,endres2024nl2postcond} map fragments back to language for correction but stop short of ratifying \emph{behaviour} rather than \emph{logic}.
  \item \textbf{Adversarial spec-weakening detection.} A second, independent agent searches for scenarios consistent with the stated intent yet permitted by the proposed contract---the elaboration-layer dual of counterexample-guided inductive synthesis \cite{solarlezama2008sketching,alur2013sygus}---repurposing vacuity and non-triviality checks (the author's prior ``ensures~true'' punt detection \cite{edmonds_article3}) as a weakening signal that no NL-to-formal translator currently emits.
  \item \textbf{Brownfield multi-source characterisation with honest characterisation semantics.} The pipeline recovers a draft contract by triangulating three evidence streams---code, issue tickets, and documentation---building on traceability and intent-mining research \cite{antoniol2002recovering,merten2015issuetracking,tan2012tcomment} but, unlike that research, reconciling the streams into a per-clause provenance-tagged contract and treating inter-stream \emph{disagreement} as the deliberate success outcome. It is also explicit that verifying code against a code-derived spec is characterisation, not proof of correctness---a precision the spec-mining literature \cite{ernst2007daikon,ammons2002mining} rarely states.
  \item \textbf{Compositional propagation for version compatibility.} Because contracts compose, a callee-spec change recomputes caller proof obligations and flags behaviourally broken call sites without execution, promoting the compositional refinement validated in Article~3 of this programme \cite{edmonds_article3} into a lifecycle capability. Internal refactors and dependency version bumps become the same operation---a blast-radius analysis the breaking-change literature \cite{ochoa2022breaking,jayasuriya2024understanding,islam2025byam} measures empirically but does not derive from a verified contract.
\end{enumerate}

These five capabilities are not novel in isolation; the contribution is their composition into a coherent reference architecture in which the formal contract is the pivot between the ambiguous human world and the precise machine world, simultaneously the agent's input and its verification oracle. The remainder of this article specifies that architecture and demonstrates its feasibility by instantiation over a real three-stream corpus, reusing the validated assets of the surrounding programme---inferred draft contracts \cite{edmonds_article1}, lossless artefact embedding \cite{edmonds_article2}, compositional refinement \cite{edmonds_article3}, and continuous-integration deployment \cite{edmonds_article4}---as trusted components, while the trusted verifier never grades itself. \Cref{tab:rw-gap} summarises which capability each major prior line supplies and where it stops short of the integrated pipeline.
