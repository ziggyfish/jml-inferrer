\section{Implementation}
\label{sec:impl}

We implement the embedder in Java~21, using ASM~9.7 for class-file rewriting. The module \texttt{com.jml:jml-embedder} is approximately 1{,}800 source lines of code at the version tagged in our replication package, of which roughly 1{,}000 are in the three core classes described below; the remainder cover the codec, the OpenAPI extension reader/writer, an automated dictionary learner used in Section~\ref{subsec:format-opt}, and small data records. The module depends only on ASM, Gson, and SLF4J. Figure~\ref{fig:pipeline} shows the data flow.

\subsection{\texttt{AsmJmlSpecWriter}}

Our writer accepts either a single class file (as \texttt{byte[]}) or a JAR (as \texttt{Path}). For a JAR, it walks each \texttt{.class} entry, applies a \texttt{ClassReader} \(\to\) \texttt{ClassVisitor} \(\to\) \texttt{ClassWriter} pipeline that intercepts \texttt{visitMethod} calls, and emits a single \texttt{@JmlSpecs} annotation per method with each clause kind as a \texttt{String[]} member. Order within each kind is preserved by array order. Clause strings are encoded via the \texttt{SpecCodec} dictionary (Section~\ref{sec:format}) before being written; the default \texttt{assignable \textbackslash nothing} member is omitted. Methods without a corresponding \texttt{MethodSpec} are passed through unchanged.

For specifications that exceed the per-class bytecode budget or for JARs that must remain unmodified, the writer also produces a sidecar JAR per Section~\ref{sec:format}. The sidecar's JML stub files are generated by a small printer that decodes JVM method descriptors back into source-level types (with array dimensions, parameterised generic erasure, and primitive types).

\subsection{\texttt{AsmJmlSpecReader}}

Our reader is symmetric: it walks each \texttt{.class} entry with a \texttt{ClassReader} configured to skip code, debug, and frames (it needs only the annotations) and accumulates a \texttt{Map<MethodKey, MethodSpec>}. It accepts both the current v2 shape (a single \texttt{@JmlSpecs} with array members per clause kind) and the legacy v1 shape (repeated \texttt{@JmlSpec} annotations with per-clause \texttt{kind}/\texttt{text}/\texttt{order} metadata, optionally wrapped in \texttt{@JmlSpecs(value=\{\dots\})}). For v2, clause strings are decoded via \texttt{SpecCodec}, and a missing \texttt{assignable} member is synthesised as \texttt{[\textbackslash nothing]}.

\subsection{\texttt{JmlCanonicaliser}}

Our canonicaliser implements the rules of Section~\ref{sec:format}. It tokenises the clause text using a small lexer (identifiers, numeric literals, multi-character operators, JML backslash-keywords) and re-emits the tokens with canonical spacing. The implementation is 260 source lines and we validate it with 16 test cases covering whitespace collapsing, operator spelling, parenthesisation, and idempotency.

\subsection{Pipeline Integration}

We integrate the embedder with the inferrer via a small bridge class, \texttt{InferrerSpecConverter}, that translates the inferrer's \texttt{MethodSpecification} model to the embedder's \texttt{MethodSpec} record. The conversion is byte-for-byte exact and preserves clause-list order; we invoke canonicalisation separately when needed. With the converter in place, the end-to-end pipeline is one method call:

\begin{lstlisting}
MethodSpecification inferred = new MethodSpecificationInferrer()
        .inferSpecification(method);
MethodSpec embeddable = InferrerSpecConverter.toEmbeddable(inferred);
new AsmJmlSpecWriter().embedJar(input, output,
        Map.of(methodKey, embeddable));
\end{lstlisting}

The roundtrip property
\texttt{extract(embed(\allowbreak{}infer(\allowbreak{}source)))~==~infer(\allowbreak{}source)}
is exercised by a JUnit suite (\texttt{InferrerToEmbedderRoundtripTest}) at small scale and at corpus scale by the validation harness of Section~\ref{sec:empirical}.
